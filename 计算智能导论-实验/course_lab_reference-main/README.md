# 深度学习上机实验参考文档

## 1. 实验目标

本次上机实验要求学生使用深度学习或相关智能算法完成一个综合实践任务。每组从以下三个方向中任选一个完成：

- 图像恢复
- 音乐去噪
- 吟诗作赋

实验重点不只是得到一个可展示的结果，还包括理解任务背景、选择合适的数据集和模型、完成可复现的实验流程，并对结果进行分析。学生可以使用公开数据集、开源代码和预训练模型，但必须清楚说明资源来源、本组完成的工作，以及实验中的修改和分析。

为降低验收成本，助教为每个任务提供固定的验收测试数据。除此之外，学生需要自行寻找合适的公开数据集用于训练和实验，并在报告中说明数据来源、规模、使用范围和预处理方式。

### 2.1 图像恢复

图像恢复（Image Inpainting）任务要求根据受损或有缺失区域的输入图像，恢复出完整、清晰的图像内容。本次课程数据以古画修复为例，要求对存在划痕、污渍、遮挡或区域缺失的图像进行修复。

典型输入：

- 受损图像

典型输出：

- 修复后的完整图像

推荐方法：

- U-Net
- Partial Convolution
- Contextual Attention（DeepFill）
- Restormer
- 预训练扩散模型（如 Stable Diffusion Inpainting）

可选评价方式：

- PSNR
- SSIM
- LPIPS
- 可视化对比
- 成功案例和失败案例分析

### 2.2 音乐去噪

音乐去噪任务要求从带噪音频中去除噪声，尽量保留原始音乐或语音内容。

典型输入：

- 带噪音频

典型输出：

- 去噪后的音频

推荐方法：

- U-Net Spectrogram Denoising
- Conv-TasNet
- Demucs
- Denoiser

可选评价方式：

- 主观听感
- 波形对比
- 频谱图对比
- SNR / SDR
- PESQ / STOI
- 成功案例和失败案例分析

### 2.3 吟诗作赋

吟诗作赋任务要求根据主题词、关键词、上句、图片描述或其他输入生成符合语义和风格要求的诗词或短文。

典型输入：

- 主题词
- 关键词
- 上句
- 风格要求

典型输出：

- 古诗、词、短文或其他文本生成结果

推荐方法：

- LSTM
- Transformer Decoder
- GPT-2 Chinese
- 中文预训练语言模型（如 Qwen、ChatGLM）

可选评价方式：

- 语义相关性
- 语言流畅性
- 格式正确性
- 风格一致性
- BLEU / ROUGE
- 人工评价和案例分析

## 3. 开源资源使用规范

本实验允许并鼓励使用公开数据集、开源代码和预训练模型。使用开源资源可以帮助学生更快进入实验本身，把重点放在理解方法、运行流程、结果分析和合理改进上。

但直接调用现成模型生成结果，且缺少原理说明、实验过程、对比分析和失败案例分析，不视为高质量完成。

报告中必须说明：

- 使用了哪些数据集
- 数据集来源和下载地址
- 使用了哪些开源代码或工具库
- 是否使用预训练模型
- 本组自己完成了哪些工作
- 对原始代码或模型做了哪些修改
- 实验结果是否可复现

## 4. 推荐完成层次

### 4.1 基础完成

达到基础完成要求的实验应包括：

- 能够运行一个深度学习方法
- 能够给出输入和输出结果
- 能够说明任务定义、方法原理和运行步骤
- 能够展示至少 3 到 5 个实验样例
- 能够对结果进行简单分析
- 能够在报告中注明数据、代码和模型来源

### 4.2 较好完成

达到较好完成要求的实验应包括：

- 使用公开数据集进行测试或训练
- 比较至少两种方法或两个设置
- 给出定量指标或清晰的人工评价标准
- 展示可视化结果，例如修复前后对比图、频谱图、生成文本示例
- 分析成功案例和失败案例
- 说明模型优缺点和改进方向


## 5. 建议实验流程

建议每组按照以下步骤完成实验：

1. 选择一个任务方向。
2. 阅读任务说明，明确输入、输出和评价方式。
3. 寻找合适的公开数据集并准备训练数据。
4. 选择一个深度学习模型或预训练模型进行实验。
6. 记录环境配置、运行命令和实验结果。
7. 对比不同方法或不同参数设置。
8. 整理成功案例、失败案例和分析。
9. 完成实验报告，并准备本地验收时需要展示的结果材料。

## 6. 提交内容

最终只需要提交实验报告。验收由助教在本地进行，验收时需要能够展示或说明代码、数据样例、运行流程和实验结果。

报告建议提交为 PDF或者word 格式。报告内容包括但不限于实验背景、实验原理、实验步骤、关键代码或代码说明、实验结果、结果分析、本人分工内容、本人对项目的理解和参考资料，其中本人分工内容和对项目的理解不可与其他成员雷同。

## 7. 实验报告建议结构

实验报告建议包含以下内容：

1. 实验背景
2. 任务定义
3. 数据集介绍
4. 实验原理或方法原理
5. 模型结构或算法流程
6. 实验环境
7. 实验步骤
8. 关键代码或代码说明
9. 实验结果
10. 对比分析
11. 失败案例分析
12. 本人分工内容
13. 本人对项目的理解

## 8. 本地验收展示建议

本地验收展示建议控制在清楚、简洁、可复现的范围内。展示内容可以包括：

- 任务目标
- 使用的数据集和模型
- 方法流程图
- 关键实验设置
- 输入输出结果
- 对比实验
- 失败案例
- 小组分工
- 总结和改进方向

图像恢复任务建议展示输入受损图像、修复后输出图像和不同方法的对比结果。音乐去噪任务建议展示波形图、频谱图，并准备去噪前后的试听片段。吟诗作赋任务建议展示输入 prompt、生成结果，以及格式、语义和风格分析。

## 9. 评分参考

评分可以参考以下维度：

- 任务完成度
- 方法理解程度
- 实验流程完整性
- 结果质量
- 对比分析充分性
- 报告清晰度
- 展示效果
- 小组分工合理性
- 开源资源引用规范性

建议避免只根据最终效果评分。对于难度不同的任务，应综合考虑学生是否完成了清晰的实验设计、可复现流程、合理分析和真实工作量。

## 10. 注意事项

- 可以使用开源数据集、代码和预训练模型，但必须注明来源。
- 不建议从零训练大型模型，除非小组有明确资源和时间。
- 报告中应明确区分开源部分和本组完成部分。
- 展示结果应尽量包含成功案例和失败案例。
- 验收时应能在本地说明代码、数据、运行流程和结果来源。
